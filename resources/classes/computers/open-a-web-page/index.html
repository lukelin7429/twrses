What Happens When You Open a Web Page?打開一個網頁，發生了什麼？

Opening a web page is a conversation between two computers. Follow it in 3D: your computer asks an address book for a number, sends a request to a server far away, and gets back a few lines of text, which the browser draws as a page. Then edit a page’s text yourself, take a web address apart, and decide who is asking and who is answering.
打開一個網頁，是兩台電腦之間的一段對話。在 3D 裡跟著走一趟：你的電腦先向地址簿問一個數字，再向遠方的伺服器送出請求，拿回幾行文字，瀏覽器把它畫成頁面。接著自己改一改網頁的文字、把一個網址拆開來看，再分辨誰在問、誰在答。

Big idea · 一句話看懂

A web page does not live on your computer. Your browser asks another computer, called a server, to send it. The server sends back a file of text, and the browser turns that text into the page you see. Before it can ask, the browser has to turn the site’s name into a number, and it does that by asking the DNS.
網頁並不放在你的電腦裡。你的瀏覽器向另一台叫做伺服器的電腦提出請求，請它把網頁送過來。伺服器送回一份文字檔，瀏覽器再把這份文字變成你看到的頁面。提出請求之前，瀏覽器得先把網站的名字換成一個數字，這件事要去問 DNS。

Unit 13: What Happens When You Open a Web Page?

You type an address, press Enter, and a page appears. It feels as if the page were already inside your computer. It is not. It is stored on another computer, perhaps in another country, and your computer has to ask for it. Opening a web page is a short conversation between two machines.

你打好網址，按下 Enter，一個網頁就出現了。感覺好像這個網頁本來就在你的電腦裡。其實不是。它存放在另一台電腦上，也許在另一個國家，你的電腦得去把它要過來。打開一個網頁，是兩台機器之間一段很短的對話。

The two machines have names. Yours is the client: your computer or phone, and the web browser on it. The other is a server: a computer that stores web pages and sends them out when asked. The client asks. The server answers. That is the pattern of the whole web.

這兩台機器各有名稱。你這一邊叫用戶端（client）：你的電腦或手機，以及上面的瀏覽器。另一邊叫伺服器（server）：一台存放網頁、有人要就送出去的電腦。用戶端發問，伺服器回答。整個全球資訊網都是照這個模式運作的。

First there is a small problem. You typed a name, such as example.com, but computers find each other by number. So the browser asks the Domain Name System, or DNS. It works like an address book: give it a name, and it gives back a number called an IP address, which looks something like 192.0.2.10. Now the browser knows where to send its question.

一開始有個小問題。你打的是一個名字，例如 example.com，可是電腦是靠數字找到彼此的。所以瀏覽器先去問網域名稱系統（Domain Name System，簡稱 DNS）。它像一本地址簿：給它一個名字，它還你一個數字，叫做 IP 位址，長得像 192.0.2.10 這樣。現在瀏覽器知道問題該往哪裡送了。

Next, the browser sends the server a request. It is a short message that says, in effect, “please send me this page.” The server answers with a code and, if all is well, the page. The code 200 means OK. The code 404 means “not found”: the server is there, but it has no page at that address.

接下來，瀏覽器向伺服器送出一個請求。那是一則很短的訊息，意思就是「請把這一頁給我」。伺服器回一個代碼；一切順利的話，還有那個網頁。代碼 200 表示「好」。代碼 404 表示「找不到」：伺服器在，只是那個位置沒有網頁。

And what is the page? It is a file of text, written in a language called HTML. Tags in the text say what each piece is: this is a heading, that is a paragraph. The browser reads the text and draws the page from it. If the page has pictures, the browser asks for each of them in the same way, one request after another.

那網頁又是什麼？它是一份文字檔，用一種叫 HTML 的語言寫成。文字裡的標籤（tag）說明每一塊是什麼：這是標題，那是一段話。瀏覽器讀了這份文字，照著把網頁畫出來。如果網頁裡有圖片，瀏覽器會用同樣的方式一張一張去要，一個請求接著一個請求。

The web is not the same thing as the internet. The internet is the worldwide network that connects the computers, and the web is one of the services that run on it. Email and instant messaging are others. Each time you tap a link, the same conversation happens again: a name, a number, a request, an answer, and a page drawn from text.

全球資訊網（Web）和網際網路（Internet）不是同一件事。網際網路是把電腦連在一起的全球性網路，全球資訊網是在它上面運作的服務之一；電子郵件和即時通訊是另外幾種。你每點一次連結，同一段對話就再發生一次：一個名字、一個數字、一個請求、一個回答，然後一個用文字畫出來的網頁。

Questions · 閱讀理解

Which computer is the client and which is the server? What does each one do?

The client is your computer or phone and its browser. It asks for a page. The server is a computer that stores web pages. It answers by sending the page.

Why does the browser ask the DNS before it asks the server?

You type a name, but computers find each other by number. The DNS turns the name into the server’s number, its IP address, so the browser knows where to send the request.

What does a server send back, and what does the browser do with it?

It sends a code, such as 200 for OK or 404 for not found, and a file of text written in HTML. The browser reads the text and draws the page from it.

Try It · 自己試試

A Web Page Is Text 網頁是一份文字

On the left is the kind of file a server sends: plain text with tags. On the right is what a browser draws from it. Change the words between the tags. Then change the color, or add another line of your own.
左邊是伺服器送來的那種檔案：帶著標籤的純文字。右邊是瀏覽器照著它畫出來的樣子。改一改標籤中間的字，再改改顏色，或自己多加一行。

What the browser draws · 瀏覽器畫出來的樣子

This little browser understands only two tags, <h1> for a heading and <p> for a paragraph, and one setting, color, with these values: black, red, green, blue, orange, purple, teal, and brown. Real HTML has many more tags, and real pages set colors in a separate language called CSS. Nothing you type here is sent anywhere.這個小瀏覽器只懂兩種標籤：<h1> 是標題、<p> 是一段話；只懂一個設定 color，可以用的值是 black、red、green、blue、orange、purple、teal、brown。真的 HTML 有多得多的標籤，真的網頁則用另一種叫 CSS 的語言來設定顏色。你在這裡打的東西不會送到任何地方。

  • Every opening tag needs its closing tag: <p> and then </p>. Leave one out and see what happens.每個開頭的標籤都要配一個結尾的標籤：<p> 配 </p>。漏掉一個，看看會怎樣。
  • The tags themselves never show on the page. They are instructions to the browser.標籤本身不會出現在網頁上。它們是給瀏覽器看的指示。
  • This is the lesson of Lesson 9 again: the browser does exactly what the text says.這又是第九課的道理：瀏覽器完全照文字寫的做。

Stories Behind the Web · 全球資訊網的故事

A project at a physics lab, a browser with pictures, a number that became famous, and a page that is not there 物理實驗室裡的一個計畫、有圖片的瀏覽器、一個出了名的數字、一個不存在的網頁

Four short stories about asking and answering.
關於「發問和回答」的四個小故事。

1989

It began at a physics laboratory它從一間物理實驗室開始

According to Britannica, the development of the World Wide Web was begun in 1989 by Tim Berners-Lee and his colleagues at CERN, an international scientific organization based in Geneva, Switzerland. They created a protocol called HTTP, which standardized communication between servers and clients, and their text-based web browser was made available for general release in January 1992. The request in this lesson’s model, “GET /pets,” is written in that protocol.
根據大英百科，全球資訊網的開發始於 1989 年，由提姆・柏內茲－李（Tim Berners-Lee）和他在 CERN 的同事著手進行；CERN 是設在瑞士日內瓦的國際科學組織。他們訂出一套叫 HTTP 的協定，把伺服器和用戶端之間的溝通方式統一起來；他們那個只有文字的瀏覽器，在 1992 年 1 月開放給大眾使用。這一課模型裡的請求「GET /pets」，就是照這套協定寫的。

1993

Point and click用點的

The first browsers showed text. Britannica says the web gained rapid acceptance with a browser called Mosaic, developed by Marc Andreessen and others at the University of Illinois and released in September 1993. Mosaic let people use the same point-and-click actions they already knew from personal computers. By the middle of the 1990s the World Wide Web had millions of active users.
最早的瀏覽器顯示的是文字。大英百科說，全球資訊網迅速被大家接受，靠的是一個叫 Mosaic 的瀏覽器；它由馬克・安德森（Marc Andreessen）等人在伊利諾大學開發，1993 年 9 月發布。Mosaic 讓人用在個人電腦上早已熟悉的「用滑鼠點一下」來操作。到了 1990 年代中期，全球資訊網已經有幾百萬名活躍的使用者。

192.0.2.10

Numbers that belong to nobody不屬於任何人的數字

Every address in this lesson’s model was chosen on purpose so that it belongs to no real site. The organization that looks after internet names keeps example.com and example.org for use as examples in documents. And an internet standard sets aside three blocks of numbers, beginning 192.0.2, 198.51.100, and 203.0.113, for use in documentation. So a textbook can print an address without pointing its readers at somebody’s real computer.
這一課模型裡的每一個地址都是特意挑的，好讓它不屬於任何真實的網站。管理網際網路名稱的機構保留了 example.com 和 example.org，專門給文件舉例用。另外有一份網際網路標準，保留了三個區段的數字（開頭是 192.0.2、198.51.100、203.0.113）給文件使用。這樣一來，課本印出一個地址，就不會把讀者引到某個人真正的電腦上。

404

The page that is not there那個不存在的網頁

Mozilla’s reference explains that 404 means the server cannot find what was asked for, and that links leading to a 404 are often called broken or dead links. While this lesson was being written, we asked CERN’s website for a page that turned out not to exist. CERN’s “page not found” page answered with a small joke: “Talking of web servers, this is a picture of the world’s first web server,” Tim Berners-Lee’s machine at CERN.
Mozilla 的參考文件說，404 表示伺服器找不到被要求的東西，而通往 404 的連結常被稱為壞掉的連結或死連結。寫這一課的時候，我們向 CERN 的網站要了一個後來發現不存在的網頁。CERN 的「找不到網頁」頁面用一個小玩笑回答：「說到網頁伺服器，這是世界上第一台網頁伺服器的照片」——柏內茲－李在 CERN 用的那一台機器。

Myth vs. Fact · 常見迷思

Four things people get wrong 四個常見的誤會

✗ Myth · 迷思The web and the internet are the same thing.全球資訊網和網際網路是同一件事。

✓ Fact · 事實The internet is the worldwide network of computers. The web is one service that runs on it; Britannica calls it the leading information retrieval service of the internet.網際網路是全世界電腦連成的網路。全球資訊網是在它上面運作的一種服務；大英百科稱它是網際網路上最主要的資訊檢索服務。

✗ Myth · 迷思A web page is a picture that the server sends.網頁是伺服器送來的一張圖。

✓ Fact · 事實The server sends text, written in HTML. The browser on your computer draws the page from that text.伺服器送來的是用 HTML 寫的文字。網頁是你電腦上的瀏覽器照著那份文字畫出來的。

✗ Myth · 迷思404 means the internet is not working.404 表示網路壞了。

✓ Fact · 事實It means the opposite: your request reached the server and the server replied. It just has no page at that address.恰恰相反：你的請求到了伺服器，伺服器也回話了，只是那個位置沒有網頁。

✗ Myth · 迷思The name you type is the server’s address.你打的名字就是伺服器的地址。

✓ Fact · 事實The name is for people. The real address is a number, and the DNS looks it up for the browser.名字是給人看的。真正的地址是一個數字，由 DNS 替瀏覽器查出來。

Before You Start · 動手之前

A few reminders 幾個提醒

  • Looking at a page’s source only shows you the text. It does not change the real page, and you should not try to change other people’s sites.看網頁的原始碼，只是看那份文字。它不會改到真正的網頁，你也不該去動別人的網站。
  • Read a web address before you tap it. The domain name tells you whose server you are about to ask.點連結之前，先讀一讀網址。網域名稱會告訴你，你即將去問的是誰的伺服器。
  • Do not type addresses you do not know just to see what happens. Ask a teacher or a parent.不要為了看看會怎樣，就亂打不認識的網址。先問老師或家長。
  • Use a school or family computer only with permission.用學校或家裡的電腦要先得到同意。

You need · 準備材料

  • Three desks labeled Client, DNS, and Server三張桌子，分別標上 Client（用戶端）、DNS、Server（伺服器）
  • A DNS sheet: two made-up site names, each with a desk number一張 DNS 表：兩個自己編的網站名稱，各配一個桌號
  • At each Server desk, a folder of “pages”: sheets of text with <h1> and <p> tags每張 Server 桌上放一個「網頁」資料夾：幾張寫著 <h1>、<p> 標籤的文字
  • Slips of paper for messages, and blank paper for drawing寫訊息用的小紙條，和畫圖用的白紙

Steps · 步驟

  1. The Client writes a site name on a slip and carries it to the DNS desk. The DNS looks it up and writes the desk number on the slip. If the name is not on the sheet, the DNS writes “no such name.”Client 在紙條上寫一個網站名稱，拿到 DNS 那一桌。DNS 查表，把桌號寫在紙條上。如果表上沒有這個名字，DNS 就寫「no such name」。
  2. The Client carries a new slip to that desk. It says, in English, “GET” and the name of a page.Client 拿一張新紙條到那個桌號的桌子，上面用英文寫「GET」和一個網頁的名字。
  3. The Server looks in the folder. If the page is there, the Server writes “200 OK” and hands over a copy of the text. If not, the Server writes “404 Not Found.”Server 在資料夾裡找。有那一頁，就寫「200 OK」並交出那份文字的副本；沒有，就寫「404 Not Found」。
  4. Back at the Client desk, another student is the browser: read the tags and draw the page on blank paper. Big letters for <h1>, ordinary writing for <p>.回到 Client 那一桌，另一位同學當瀏覽器：讀標籤，在白紙上把網頁畫出來。<h1> 寫成大字，<p> 寫成一般的字。

Count the trips: two round trips for one page. Then put a picture on a page, kept in a separate folder, and count again. In Taiwan’s junior high Information Technology curriculum, this lesson matches the topic “System platforms”: 資 S-IV-3, concepts of network technology, and 資 S-IV-4, concepts of network services, whose notes name the World Wide Web as an internet service.
數一數走了幾趟：一個網頁要來回兩趟。接著在網頁裡放一張圖（圖放在另一個資料夾），再數一次。對照十二年國教國中「資訊科技」的學習內容，這一課對應「系統平台」主題：資 S-IV-3 網路技術的概念與介紹、資 S-IV-4 網路服務的概念與介紹（附錄的說明把全球資訊網列為網際網路服務之一）。

Classroom Activity 2 · 課堂活動二

Check It on Your Own Computer 在自己的電腦上驗證

You need · 準備材料

  • A computer with the Firefox browser, or another browser一台有 Firefox 瀏覽器的電腦，或其他瀏覽器
  • This lesson’s page這一課的網頁
  • Paper and a pencil紙和鉛筆

Steps · 步驟

  1. Look at the address bar. Write down the address of this page and mark its three parts: protocol, domain name, and path.看網址列。把這一頁的網址抄下來，標出三個部分：協定、網域名稱、路徑。
  2. In Firefox, right-click an empty part of the page and choose View Page Source. A new tab opens with the text the server sent.Firefox：在網頁空白的地方按右鍵，選 View Page Source。會開一個新分頁，裡面就是伺服器送來的文字。
  3. Find one <h1> tag and one <p> tag in the text. What words are between them? Find the same words on the page.在文字裡找一個 <h1> 標籤和一個 <p> 標籤。它們中間是什麼字？在網頁上找出同樣的字。
  4. Now change the end of the address to a page that surely does not exist, such as /no-such-page/, and press Enter. What does the server say?接著把網址的結尾改成一個肯定不存在的頁面，例如 /no-such-page/，按 Enter。伺服器說什麼？

Other browsers have a similar command, and the name differs a little from one to another. The real page is much longer than the model’s, with many more kinds of tags, but it is the same kind of thing: text. And the last step should give you a real 404.
其他瀏覽器也有類似的指令，名稱各家略有不同。真的網頁比模型裡的長得多，標籤的種類也多得多，但它是同一種東西：文字。最後一步，你應該會拿到一個真正的 404。
