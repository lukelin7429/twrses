Big idea · 一句話看懂

A processor does the same three small steps over and over: fetch an instruction from memory, decode it, and execute it. Each step is tiny. A processor is powerful only because it repeats this loop billions of times a second.
處理器一直重複同樣三個小步驟：從記憶體拿一條指令、看懂它、照著做。每一步都很小。處理器厲害的地方，只在於它每秒能把這個迴圈重複幾十億次。

    Unit 6: What Does a Processor Do All Day?

    In Lesson 5 you found the processor, a small square hiding under a big cooler, and you learned that it carries out the instructions of programs. But what does that actually look like? The answer is surprisingly plain. A processor does the same three small steps, over and over, for as long as the power is on. It fetches an instruction, decodes it, and executes it.

    在第五課，你找到了處理器，一片躲在大散熱器底下的小方塊，也知道它負責執行程式的指令。可是「執行指令」到底是什麼樣子？答案出乎意料地平淡。只要有電，處理器就一直重複同樣三個小步驟：拿一條指令、看懂它、照著做。

    A program is a list of instructions kept in memory. The processor has a small counter that holds the place of the next instruction. To fetch, the processor looks at the counter and copies the instruction at that place out of memory. In the model, the counter starts at 0, so the first instruction comes from cell 0.

    程式是一串放在記憶體裡的指令。處理器有一個小小的計數器，記著下一條指令在哪裡。要「拿」指令的時候，處理器看一下計數器，把那個位置的指令從記憶體抄出來。在模型裡，計數器從 0 開始，所以第一條指令來自第 0 格。

    Next the processor decodes the instruction, which means working out what it is asking for. Our model understands only five instructions. LOAD copies a number from memory into the processor. ADD adds a number from memory to it, using an adder like the one in Lesson 4. STORE copies the result back into memory. Then the processor executes the instruction: it does that one small thing and nothing more.

    接著處理器要「看懂」這條指令，也就是弄清楚它在要求什麼。我們的模型只懂五種指令。LOAD 把記憶體裡的一個數抄進處理器；ADD 把記憶體裡的一個數加上去，用的是像第四課那樣的加法器；STORE 把結果抄回記憶體。然後處理器「照著做」：就做那一件小事，不多做別的。

    After that, the counter goes up by one, and the three steps begin again with the next instruction. Adding 3 and 4 takes four instructions. The fourth kind of instruction, JUMP, is different. It changes the counter itself, so the processor goes back and repeats instructions it has already done. That is how a program only a few lines long can keep a processor busy all day. The fifth, STOP, ends the program.

    做完之後，計數器加一，三個步驟又從下一條指令重新開始。把 3 和 4 加起來要四條指令。第四種指令 JUMP 不一樣：它改的是計數器本身，所以處理器會回頭，把做過的指令再做一次。就是因為這樣，一個只有幾行的程式，可以讓處理器忙上一整天。第五種指令 STOP 讓程式結束。

    Each step is tiny, so the power of a processor comes from speed. A clock inside it sets the pace. Clock speed is measured in gigahertz, which means billions of cycles per second: a 3.2-gigahertz processor goes through 3.2 billion cycles every second. A cycle is not exactly one instruction. Some instructions take several cycles, and sometimes several instructions finish in one. Many processors also contain more than one core, so the work can be shared among them.

    每一步都很小，所以處理器的本事來自「快」。它裡面有一個時脈在打拍子。時脈的快慢用 GHz（吉赫）來表示，意思是每秒幾十億個週期：一顆 3.2 GHz 的處理器，每秒走過 32 億個週期。一個週期不等於剛好一條指令：有的指令要好幾個週期，有時候一個週期可以做完好幾條。很多處理器裡面還不只一個核心，工作可以分給它們一起做。

    Keeping the program in the same memory as the numbers was one of the great ideas in computing. In 1945 the mathematician John von Neumann described a stored-program computer in a widely read report. On June 21, 1948, at the University of Manchester in England, a machine nicknamed the Baby ran the first program ever stored in the memory of an electronic computer. It was seventeen instructions long. With a stored program, the same processor, doing the same three steps, can become a calculator, a game, or a music player. You only have to load a different program.

    把程式和數放在同一個記憶體裡，是電腦史上很了不起的一個想法。1945 年，數學家約翰・馮紐曼（John von Neumann）在一份流傳很廣的報告裡，描述了這種「儲存程式」的電腦。1948 年 6 月 21 日，在英國的曼徹斯特大學，一台綽號叫「Baby」的機器，跑出了史上第一個存在電子電腦記憶體裡的程式，一共十七條指令。有了儲存的程式，同一顆處理器、做同樣三個步驟，就可以變成計算機、遊戲機或音樂播放器，只要換一個程式載進去就行了。

    Questions · 閱讀理解

    What three steps does a processor repeat?

    It fetches an instruction from memory, decodes it (works out what it asks for), and executes it (does it). Then it moves on to the next instruction.

    What does the counter do, and how does a JUMP instruction change it?

    The counter holds the place of the next instruction, and it normally goes up by one after each instruction. A JUMP sets the counter to a different place, so the processor can go back and repeat instructions.

    A 3.2-gigahertz processor goes through 3.2 billion cycles every second. Does that mean it carries out exactly 3.2 billion instructions every second? Why or why not?

    No. A cycle is not exactly one instruction. Some instructions take several cycles, and sometimes several instructions finish in a single cycle.

      Stories Behind the Loop · 這個迴圈的故事

      A report, a Baby, a clock, and a cell that could be anything 一份報告、一個 Baby、一個時脈、一格什麼都可能是的記憶體

      Four short stories about programs and the processors that run them.
      關於程式、以及執行程式的處理器的四個小故事。

      1945 · von Neumann

      The program moves into memory程式搬進記憶體

      The earliest electronic computers were set up for each new job by hand, with plugboards, punched cards, and paper tape. In 1945 the mathematician John von Neumann wrote the First Draft of a Report on the EDVAC. This widely circulated paper outlined a stored-program computer, in which programming information is kept electronically, just like the data. The model on this page works that way: instructions and numbers sit side by side in the same eight cells.
      最早的電子電腦，每換一件工作就要動手重新設定：插接線板、打孔卡、紙帶。1945 年，數學家馮紐曼寫了〈EDVAC 報告初稿〉。這份流傳很廣的文件，勾勒出「儲存程式電腦」的架構：程式和資料一樣，用電子的方式存起來。這一頁的模型就是這樣運作的：指令和數並排放在同樣那八個格子裡。

      June 21, 1948 · Manchester

      Seventeen instructions十七條指令

      At the University of Manchester, Frederic Williams, Tom Kilburn, and Geoff Toothill built a small machine to test a new kind of memory. Its official name was the Small-Scale Experimental Machine, but it is better known as the Manchester Baby. Its first program was written by Kilburn and was seventeen instructions long. It ran on June 21, 1948. The Computer History Museum calls it the first program in history to run on a digital, electronic, stored-program computer.
      在曼徹斯特大學，威廉斯（Frederic Williams）、基爾本（Tom Kilburn）和圖希爾（Geoff Toothill）做了一台小機器，用來測試一種新的記憶體。它的正式名稱是「小型實驗機」，但大家比較常叫它「曼徹斯特 Baby」。它的第一個程式是基爾本寫的，一共十七條指令，在 1948 年 6 月 21 日執行。電腦歷史博物館說，這是史上第一個在數位、電子、儲存程式的電腦上執行的程式。

      GHz · 時脈

      What the clock number means時脈那個數字是什麼意思

      The speed printed on a processor’s box is its clock speed. One gigahertz is one billion cycles per second, so 3.2 GHz is 3.2 billion cycles every second. During each cycle, billions of transistors inside the processor open and close. Older processors were measured in megahertz, or millions of cycles per second. Intel points out that clock speed is only one thing to look at: the number of cores matters, too.
      處理器包裝盒上印的那個速度，是它的時脈頻率。1 GHz 是每秒十億個週期，所以 3.2 GHz 就是每秒 32 億個週期。每一個週期裡，處理器裡面有幾十億個電晶體在開和關。比較早的處理器是用 MHz 來算的，也就是每秒幾百萬個週期。英特爾提醒，時脈只是該看的其中一項，核心的數目也很重要。

      0 … 7

      Is this cell an instruction or a number?這一格是指令還是數？

      In Lesson 2 you learned that bits do not say what they are. The same is true here. The processor never checks whether a cell is “meant” to be an instruction. Whatever the counter points to, it tries to obey. In the model, if the counter reaches a cell with a number or nothing in it, the processor has to stop. Try it in the activity above by leaving out STOP. Keeping the counter away from the data is the programmer’s job.
      第二課說過，位元自己不會說它是什麼。這裡也是一樣。處理器從來不會檢查某一格「本來是不是」指令：計數器指到哪一格，它就想照那一格做。在模型裡，如果計數器走到一格放的是數、或什麼都沒有，處理器就只好停下來。在上面的活動裡故意不放 STOP，就能看到這件事。不讓計數器闖進資料裡，是寫程式的人的責任。

      Myth vs. Fact · 常見迷思

      Four things people get wrong 四個常見的誤會

      ✗ Myth · 迷思A processor does big, complicated things in one go.處理器一次就能做很大、很複雜的事。

      ✓ Fact · 事實Each instruction is tiny: copy one number, add two numbers, change the counter. Big jobs are long lists of tiny steps, done very fast.每條指令都很小：抄一個數、把兩個數加起來、改一下計數器。大事情是一長串的小步驟，只是做得非常快。

      ✗ Myth · 迷思A 3 GHz processor carries out exactly 3 billion instructions a second.3 GHz 的處理器每秒剛好執行 30 億條指令。

      ✓ Fact · 事實Gigahertz counts clock cycles, not instructions. Some instructions take several cycles, and sometimes several instructions finish in one cycle.GHz 數的是時脈的週期，不是指令。有的指令要好幾個週期，有時候一個週期可以做完好幾條。

      ✗ Myth · 迷思The processor understands the program it is running.處理器懂它正在跑的程式是在做什麼。

      ✓ Fact · 事實It has no idea whether it is running a game or doing your homework. It only fetches the next instruction and does what that one instruction says.它完全不知道自己是在跑遊戲還是在算你的作業。它只是拿下一條指令，照那一條說的做。

      ✗ Myth · 迷思A program always runs from the first line to the last, once.程式一定是從第一行跑到最後一行，跑一次就結束。

      ✓ Fact · 事實A jump can send the processor back to repeat instructions, thousands or millions of times. Most of what a processor does all day is repeating.跳躍指令可以把處理器送回去，把同樣幾條指令重複幾千次、幾百萬次。處理器整天在做的，大部分就是重複。

      Before You Start · 動手之前

      The Human Processor 人體處理器

      You need · 準備材料

      • Eight sheets of paper numbered 0 to 7, taped in a row on the board: the memory八張紙，編號 0 到 7，在黑板上貼成一排：這是記憶體
      • Cards for the program: LOAD 5, ADD 6, STORE 7, STOP, and the numbers 3, 4, and 0程式用的卡片：LOAD 5、ADD 6、STORE 7、STOP，以及數字 3、4、0
      • Two small whiteboards: one for the counter, one for A兩塊小白板：一塊當計數器，一塊當 A

      Steps · 步驟

      1. Put the four instruction cards on sheets 0 to 3, and the numbers 3, 4, and 0 on sheets 5, 6, and 7. One student holds the counter, which starts at 0. Another holds A.把四張指令卡放在第 0 到 3 張紙上，把 3、4、0 放在第 5、6、7 張紙上。一位同學拿計數器（從 0 開始），另一位拿 A。
      2. A third student is the processor. Fetch: read the counter, walk to that sheet, and read the card aloud.第三位同學當處理器。拿：看一下計數器，走到那一張紙前面，把卡片大聲唸出來。
      3. Decode: say in your own words what the card asks for. Execute: do exactly that, and nothing else. Then the counter student adds one.看懂：用自己的話說出這張卡片要做什麼。照做：就做那一件事，不多做別的。然後拿計數器的同學把數字加一。
      4. Repeat until you reach STOP. Then swap ADD 6 and LOAD 5 and run it again. What ends up on sheet 7 this time, and why?一直重複到 STOP 為止。接著把 ADD 6 和 LOAD 5 的位置對調，再跑一次。這次第 7 張紙上是什麼？為什麼？

      With the two cards swapped, sheet 7 ends up with 3, not 7. The processor student did nothing wrong. The order of the instructions was wrong, and the processor obeyed it anyway. In Taiwan’s junior high Information Technology curriculum, this lesson matches the topic “System platforms”: 資 S-IV-2, whose notes list the CPU and memory.
      兩張卡片對調之後，第 7 張紙上會是 3，不是 7。當處理器的同學並沒有做錯：錯的是指令的順序，而處理器照樣照著做了。對照十二年國教國中「資訊科技」的學習內容，這一課對應「系統平台」主題：資 S-IV-2 系統平台之組成架構與基本運作原理（附錄的說明列有 CPU、記憶體）。

      Classroom Activity 2 · 課堂活動二

      Check It on Your Own Computer 在自己的電腦上驗證

      You need · 準備材料

      • A Windows or Mac computer一台 Windows 或 Mac 電腦
      • Paper and a pencil紙和鉛筆

      Steps · 步驟

      1. On a Mac, open the Activity Monitor app and click CPU. On Windows, open Task Manager and select the Performance tab.Mac：打開「活動監視器」（Activity Monitor），按 CPU。Windows：打開「工作管理員」（Task Manager），選 Performance（效能）分頁。
      2. With nothing much running, read how busy the processor is. On a Mac, look at the Idle percentage at the bottom of the window. Write the number down.在沒開什麼程式的時候，看看處理器有多忙。Mac 上看視窗最下面的「閒置」（Idle）百分比。把數字寫下來。
      3. Now open several apps or a video, and watch the numbers change. Close them and watch again.接著打開幾個 App 或一段影片，看數字怎麼變。把它們關掉，再看一次。
      4. Find how many cores your processor has. On Windows, the Performance tab lists the cores. On a Mac, choose Window > CPU History to see a graph of recent processor activity.找出你的處理器有幾個核心。Windows 的 Performance 分頁會列出核心數；Mac 選「視窗」＞「CPU 記錄」（CPU History），可以看到處理器最近活動的圖。

      Apple’s guide says that most of the time, the processor uses only a small percentage of its processing power. So what does a processor do all day? Much of the time it is waiting for something to do. When you ask for something that needs heavy calculation, it gets busy. The names of menus differ a little between versions of Windows and macOS.
      Apple 的說明寫道，大部分的時候，處理器只用到它運算能力的一小部分。所以處理器整天在忙什麼？很多時候，它其實在等事情做；等你要它做需要大量計算的事，它才忙起來。不同版本的 Windows 和 macOS，選單的名稱會略有不同。
